MACBOOK PRO SETUP

1. Install Python 3.11 with an OpenSSL-backed build if it is not already present.
   The proven interpreter on the originating Mac was Python 3.11.16. With an
   existing Homebrew installation, the usual command is:

   brew install python@3.11

2. Install Apple's Command Line Tools if needed:

   xcode-select --install

3. Open Terminal in the extracted SparkBench folder and run:

   bash tools/bootstrap_macos.sh

   This creates a fresh .venv, installs the pinned development tools and the
   local package, runs offline tests, and reports readiness. Network access is
   required for installation. It does not flash, open a serial port, request
   camera permission, or record video.

4. Connect the iPhone 15 with its data cable. Keep its working native Continuity
   Camera configuration. Point it at the rig, disable video effects/automatic
   reframing and use a stable overhead phone mount for measurements. Close other
   camera previews before SparkBench capture. Do not record audio.

5. Run these from the project folder:

   PYTHONPATH=src .venv/bin/python -m sparkbench camera authorize
   PYTHONPATH=src .venv/bin/python -m sparkbench camera list

   Allow the native camera prompt on the MacBook Pro. If denied, use System
   Settings > Privacy & Security > Camera for the launching app. A Codex runner
   may need camera commands executed outside its file sandbox. On the old Mac,
   sandboxed discovery reported denied/empty while the normal host permission
   was authorized. Do not conclude that an empty sandboxed list means no camera.

6. Select the exact iPhone camera ID from the new listing. Do not use a camera
   index or old device ID, and do not silently choose the built-in Mac camera.

   PYTHONPATH=src .venv/bin/python -m sparkbench camera capture --device-id 'CAMERA_ID' --seconds 10 --fps 5

   Replace CAMERA_ID before running. The helper recompiles locally for this Mac.
   Capture creates a new runs/camera directory with JPEGs, frames.jsonl and
   capture.json. Existing output directories are rejected. Images remain local.

7. Inspect a saved image: both LED locations and OLED text must be visible.
   This proves acquisition only. It does not establish a physical pass/fail.
   An interrupted capture can remain marked recording; inspect the final report.
